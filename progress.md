## Codec evidence (FSK, synthetic — 2026-10-17)

`npm run test:acoustic` in `attendance-frontend` — the original codec file is still **12/12**, and the full acoustic suite (codec + lab + worklets + TX/RX link + 1.9a pairing) is **51/51**. The codec numbers below are from the seeded PRNG and remain reproducible:

| Test | Result |
| --- | --- |
| Clean frames, 48 kHz, 1000 random keys | 1000/1000 decoded |
| Clean frames, 44.1 kHz, 200 keys | 200/200 decoded |
| Frame found behind 0–500 ms leading silence (search mode) | 100/100 |
| Full-band SNR 30 / 20 / 10 / 0 dB (100 keys each) | 100/100 each |
| Echo (single tap, gain 0.5) at 30 / 60 / 90 ms | 50/50 each |
| Echo 60 ms + 10 dB noise | 50/50 |
| False positives: white noise only / random tone sequences | 0/100 and 0/30 |
| Check symbols: single tone flips rejected | 0/200 accepted |
| Check symbols: two tone flips | 2/200 accepted (checksum collisions, ~1 in 225 expected) |

Codec facts as built: 17 tones at 110 Hz spacing from 18.0 kHz; 120 ms symbols; frame = 2 marker + 7 data + 2 check symbols (1.32 s); data digits base 15; consecutive data/check tones can never repeat (carried by construction, inverted by the decoder); check digits = weighted sum mod 225; 6 ms raised-cosine fade per symbol; detection = ≥9 dB above the median of the 17 tones. Caveat: this is synthetic audio — real speaker/mic behaviour is still untested (that is what the lab run and slice 1.8 are for).

## Open items (from `plan.md`)

- **The 2.4b/2.4c/2.5 UI still needs a real Google/phone rehearsal:** the local smokes used a JWT cookie and, for 2.4b, a fake audio file. Validate the consent wording, mic permission flow, evidence screen, advance confirmation and wave-change stop on the target Android devices.
- **The student cascade is not built:** the server can advance waves and keep bounded key history, but students do not receive or transmit the next key. The "lowest wave heard" rule and multi-hop cascade remain future work; the current pilot is teacher-driven waves plus evidence.
- **Device-binding retention is undefined:** binding records persist indefinitely, while proof evidence is TTL'd after about 24 hours. Clarify whether bindings follow the same retention or persist until a device change; the agreed 1-day evidence retention is unchanged.
- **First-binding recovery boundary:** the first binding for a never-bound account is auto-approved, so a stolen session cookie can bind a device. Account/device theft is out of current scope, but wording must say "once a device key is bound" rather than implying a copied cookie can never submit a proof.
- **CSRF split-hosting caveat:** the CSRF origin guard requires the exact frontend origin in `CLIENT_URLS`. Same-origin single-service hosting is automatic; CLI requests with no `Origin` header still work.
- **Startup fails closed on duplicate data:** a duplicate that prevents a unique index from building stops the service. Clean duplicate rows before deploying.
